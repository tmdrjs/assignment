# 소코반(Sokoban) 웹 게임 요구사항

## 1. 프로젝트 개요

### 목적

브라우저에서 바로 즐길 수 있는 소코반 퍼즐 게임을 만든다.

설치, 회원가입, 로그인 없이
접속하는 즉시 플레이할 수 있어야 한다.

### 대상

- 퍼즐 게임을 가볍게 즐기려는 일반 사용자
- 짧은 시간에 머리를 쓰는 게임을 찾는 사용자
- PC와 모바일 모두에서 플레이하는 사용자

### 핵심 목표

1. 규칙을 설명하지 않아도 1스테이지에서 자연스럽게 익힐 수 있다.
2. 조작이 즉각적으로 반응한다.
3. 실수했을 때 되돌리기가 쉽다.
4. 어디까지 진행했는지 항상 알 수 있다.
5. PC 키보드와 모바일 터치 모두 불편함이 없다.

### 범위에서 제외하는 것

- 서버, 데이터베이스, 계정 시스템
- 온라인 랭킹, 멀티플레이
- 결제, 광고
- 레벨 에디터

모든 데이터는 브라우저 안에서만 처리한다.


## 2. 기술 스택

- React
- TypeScript
- Vite
- CSS (또는 CSS Module)

게임 엔진, 캔버스 라이브러리, 상태 관리 라이브러리를 사용하지 않는다.

게임 보드는 DOM으로 렌더링한다.
소코반은 격자 기반 턴제 게임이므로 캔버스가 필요하지 않다.

요구사항에 없는 라이브러리를 임의로 설치하지 않는다.


## 3. 게임 규칙

소코반의 표준 규칙을 그대로 따른다.

### 구성 요소

- 벽(Wall): 통과할 수 없다.
- 바닥(Floor): 이동할 수 있다.
- 목표 지점(Goal): 상자를 올려야 하는 칸이다.
- 상자(Box): 밀 수 있다.
- 플레이어(Player): 사용자가 조작한다.

### 이동 규칙

1. 플레이어는 상하좌우 한 칸씩 이동한다.
2. 대각선 이동은 없다.
3. 이동하려는 칸이 벽이면 이동할 수 없다.
4. 이동하려는 칸에 상자가 있으면 상자를 민다.
5. 상자를 밀 때, 상자 뒤 칸이 벽이거나 다른 상자면 밀 수 없다.
6. 상자는 밀 수만 있고 당길 수 없다.
7. 한 번에 상자 하나만 밀 수 있다.

### 클리어 조건

모든 상자가 목표 지점 위에 올라가면 스테이지를 클리어한다.

상자 개수와 목표 지점 개수는 항상 같다.


## 4. 레벨 데이터 형식

레벨은 표준 소코반 표기법(XSB) 문자열 배열로 정의한다.

| 문자 | 의미 |
| --- | --- |
| `#` | 벽 |
| ` ` | 바닥 |
| `.` | 목표 지점 |
| `$` | 상자 |
| `*` | 목표 지점 위의 상자 |
| `@` | 플레이어 |
| `+` | 목표 지점 위의 플레이어 |

### 레벨 정의 구조

각 레벨은 다음 정보를 가진다.

- id: 스테이지 번호
- name: 스테이지 이름
- difficulty: easy / normal / hard
- map: 문자열 배열
- minMoves: 최소 이동 수 (선택)

### 예시 1 — 튜토리얼

```
#######
#     #
# .$@ #
#     #
#######
```

왼쪽으로 한 번만 밀면 클리어된다.
조작 방법을 익히기 위한 스테이지다.

### 예시 2 — 상자 2개

```
#########
#       #
#  $ .  #
#  @    #
#  $ .  #
#       #
#########
```

### 데이터 검증 규칙

레벨 데이터를 추가할 때 다음을 반드시 확인한다.

- 플레이어는 정확히 1명이다.
- 상자 개수와 목표 지점 개수가 같다.
- 플레이 영역이 벽으로 완전히 닫혀 있다.
- 실제로 클리어 가능한 레벨이다.

클리어 불가능한 레벨을 추가하지 않는다.
검증하지 않은 레벨을 임의로 만들어 넣지 않는다.


## 5. 화면 구성

화면은 3개로 구성한다.

1. 시작 화면
2. 스테이지 선택 화면
3. 게임 화면

라우터 라이브러리 없이 상태로 화면을 전환한다.


## 6. 시작 화면

### 구성

- 게임 타이틀
- 시작 버튼 (이어하기 / 새로 시작)
- 스테이지 선택 버튼
- 조작 방법 안내

### 동작

- 저장된 진행 기록이 있으면 "이어하기"를 기본 버튼으로 표시한다.
- 저장된 기록이 없으면 "시작하기"만 표시한다.

### 조작 방법 안내

간단한 텍스트와 아이콘으로 표시한다.

- 방향키 또는 WASD로 이동
- 상자를 밀어 목표 지점에 올리기
- 되돌리기: Z
- 다시 시작: R

설명이 길어지지 않도록 한다.


## 7. 스테이지 선택 화면

### 구성

- 스테이지 카드 그리드
- 뒤로 가기 버튼

### 스테이지 카드

각 카드에 다음을 표시한다.

- 스테이지 번호
- 클리어 여부
- 최고 기록 (이동 수)

### 잠금 규칙

- 이전 스테이지를 클리어해야 다음 스테이지가 열린다.
- 잠긴 스테이지는 비활성 상태로 표시하고 클릭할 수 없다.
- 1스테이지는 항상 열려 있다.


## 8. 게임 화면

### 레이아웃

상단:

- 스테이지 번호 / 이름
- 이동 수
- 밀기 수
- 경과 시간

중앙:

- 게임 보드

하단:

- 되돌리기 버튼
- 다시 시작 버튼
- 스테이지 목록 버튼
- 모바일 방향 버튼

### 게임 보드

- 격자를 정사각형 타일로 렌더링한다.
- 맵 크기에 따라 타일 크기를 자동으로 계산한다.
- 보드는 화면 중앙에 배치한다.
- 보드가 화면을 벗어나지 않도록 한다.

타일 크기는 화면 크기와 맵의 행/열 수를 기준으로 계산한다.


## 9. 조작

### 키보드

| 키 | 동작 |
| --- | --- |
| 방향키 | 이동 |
| W A S D | 이동 |
| Z | 되돌리기 |
| R | 다시 시작 |
| Esc | 스테이지 목록 |

- 키를 누르고 있으면 연속 이동이 가능해야 한다.
- 방향키 입력으로 페이지가 스크롤되지 않도록 기본 동작을 막는다.

### 모바일

- 스와이프로 이동한다.
- 화면 하단에 방향 버튼을 함께 제공한다.
- 되돌리기, 다시 시작 버튼을 항상 누를 수 있는 위치에 배치한다.
- 터치 영역은 충분히 크게 만든다.

### 마우스

마우스 조작은 지원하지 않는다.
클릭 이동, 경로 탐색 기능은 만들지 않는다.


## 10. 게임 기능

### 이동 수 / 밀기 수

- 이동 수: 플레이어가 움직인 횟수
- 밀기 수: 상자를 민 횟수

두 값을 게임 화면 상단에 항상 표시한다.

### 되돌리기 (Undo)

- 되돌리기 횟수에 제한을 두지 않는다.
- 이동 직전 상태로 정확하게 복원한다.
- 플레이어 위치, 상자 위치, 이동 수, 밀기 수를 모두 되돌린다.
- 되돌릴 기록이 없으면 버튼을 비활성화한다.

### 다시 시작 (Reset)

- 스테이지를 초기 상태로 되돌린다.
- 이동 수, 밀기 수, 시간, 되돌리기 기록을 모두 초기화한다.

### 타이머

- 첫 입력이 발생한 시점부터 시간을 센다.
- 클리어하면 멈춘다.
- 분:초 형식으로 표시한다.

### 막힘 안내 (선택)

상자가 코너에 밀려 더 이상 클리어할 수 없는 상태가 되면
"다시 시작하거나 되돌리세요" 정도의 안내를 표시할 수 있다.

단, 게임을 자동으로 중단시키지 않는다.
판정이 애매하면 이 기능을 넣지 않는다.

### 만들지 않는 기능

- 자동 풀이
- 힌트
- 이동 경로 표시
- 스테이지 건너뛰기


## 11. 클리어

### 판정

이동이 끝날 때마다 모든 상자가 목표 지점 위에 있는지 확인한다.

### 클리어 화면

보드 위에 오버레이로 결과를 표시한다.

표시 내용:

- 클리어 문구
- 이동 수
- 밀기 수
- 소요 시간
- 최고 기록 갱신 여부

버튼:

- 다음 스테이지
- 다시 하기
- 스테이지 목록

마지막 스테이지를 클리어하면
"다음 스테이지" 대신 전체 완료 메시지를 표시한다.

### 기록 갱신

- 이동 수가 더 적으면 최고 기록을 갱신한다.
- 갱신된 경우 화면에 명확하게 표시한다.


## 12. 저장

localStorage에 진행 상황을 저장한다.

### 저장 항목

- 클리어한 스테이지 목록
- 스테이지별 최고 이동 수
- 스테이지별 최고 시간
- 마지막으로 플레이한 스테이지

### 저장 시점

- 스테이지를 클리어했을 때
- 스테이지에 진입했을 때

### 예외 처리

- 저장 데이터가 없으면 초기 상태로 시작한다.
- 저장 데이터가 손상되었으면 초기화하고 게임을 정상 실행한다.
- 저장 실패가 게임 진행을 막지 않도록 한다.

### 초기화

설정 또는 시작 화면에서 진행 기록을 초기화할 수 있도록 한다.
초기화 전에 확인 단계를 둔다.


## 13. 스테이지 구성

최소 10개 스테이지를 제공한다.

난이도 구성:

- 1 ~ 3: 상자 1 ~ 2개, 규칙을 익히는 단계
- 4 ~ 7: 상자 3 ~ 4개, 순서를 생각해야 하는 단계
- 8 ~ 10: 코너와 좁은 통로를 활용한 단계

난이도가 갑자기 뛰지 않도록 한다.
1스테이지는 반드시 몇 번의 이동으로 클리어할 수 있어야 한다.


## 14. 상태 관리 구조

### 게임 상태

- 현재 스테이지 번호
- 정적 맵 (벽, 목표 지점)
- 플레이어 위치
- 상자 위치 목록
- 이동 기록 (되돌리기용)
- 이동 수, 밀기 수
- 시작 시간
- 클리어 여부

### 원칙

- 벽과 목표 지점은 변하지 않으므로 별도로 보관한다.
- 매 이동마다 맵 전체를 문자열로 다시 만들지 않는다.
- 이동 판정 로직은 UI와 분리한다.
- 순수 함수로 이동 로직을 구현해서 테스트하기 쉽게 만든다.

### 파일 구성 예시

- 게임 로직
- 레벨 데이터
- 저장 처리
- 화면 컴포넌트

한 파일에 모든 코드를 넣지 않는다.


## 15. 디자인 방향

### 전체 분위기

- 미니멀
- 정돈된 느낌
- 퍼즐 게임다운 차분한 분위기
- 과도한 장식 금지

### 색상

제한된 색상만 사용한다.

- 배경
- 벽
- 바닥
- 목표 지점: 포인트 색상
- 상자: 기본 색상
- 목표 지점 위의 상자: 완료 색상
- 플레이어: 강조 색상

상자가 목표 지점에 올라간 상태를 한눈에 구분할 수 있어야 한다.
이 구분을 색상만으로 하지 말고 형태나 표시를 함께 사용한다.

### 타일 표현

- 이미지 대신 CSS로 표현한다.
- 도형과 색상만으로 각 요소를 구분한다.
- 이미지 에셋을 사용하는 경우 최소한으로 사용한다.

### 타이포그래피

- 숫자(이동 수, 시간)는 고정폭 폰트를 사용해 흔들리지 않게 한다.
- 정보 표시는 읽기 쉬운 크기를 우선한다.


## 16. 애니메이션

애니메이션은 최소한으로 사용한다.

사용 가능한 영역:

- 플레이어 이동
- 상자 이동
- 목표 지점 달성 순간
- 클리어 오버레이 등장
- 버튼 hover

### 원칙

- 이동 애니메이션은 짧게 한다. (100ms 내외)
- 애니메이션이 다음 입력을 막지 않도록 한다.
- 연속으로 빠르게 입력해도 끊기거나 밀리지 않아야 한다.
- 화면 전체가 흔들리는 효과를 사용하지 않는다.

조작감이 애니메이션보다 우선이다.


## 17. 사운드

사운드는 기본적으로 넣지 않는다.

넣는 경우 다음을 지킨다.

- 기본값은 음소거
- 끄고 켜는 버튼 제공
- 설정을 저장
- 접속하자마자 소리가 나지 않도록 한다.


## 18. 반응형

### Desktop

- 보드를 화면 중앙에 크게 배치한다.
- 키보드 조작을 기본으로 한다.
- 모바일 방향 버튼은 표시하지 않는다.

### Tablet

- 보드 크기를 자연스럽게 조정한다.

### Mobile

- 보드가 화면 안에 완전히 들어와야 한다.
- 하단에 방향 버튼을 배치한다.
- 상단 정보 영역을 간결하게 줄인다.
- 가로 스크롤이 발생하지 않도록 한다.
- 스와이프 중 페이지가 함께 스크롤되지 않도록 한다.


## 19. UX

사용자가 처음 접속했을 때 다음을 바로 알 수 있어야 한다.

1. 어떤 게임인가?
2. 어떻게 시작하는가?
3. 어떻게 움직이는가?
4. 무엇을 하면 클리어인가?
5. 실수하면 어떻게 되돌리는가?
6. 지금 몇 스테이지인가?

### 그 외

- 입력에 즉시 반응한다.
- 이동할 수 없는 방향을 눌렀을 때 아무 일도 일어나지 않게 두지 말고 짧게 반응을 준다.
- 클리어 후 다음 스테이지로 넘어가는 동선을 가장 짧게 만든다.


## 20. 접근성

- semantic HTML 사용
- 버튼은 button 요소로 만든다.
- 키보드만으로 모든 화면을 조작할 수 있게 한다.
- 포커스 상태를 명확하게 표시한다.
- 충분한 색상 대비를 확보한다.
- 상자의 완료 상태를 색상만으로 구분하지 않는다.
- 모바일 터치 영역을 충분히 확보한다.
- 게임 상태 변화를 화면에 텍스트로도 표시한다.


## 21. 성능

- 이동할 때 필요한 부분만 다시 렌더링한다.
- 매 프레임마다 전체 보드를 새로 만들지 않는다.
- 타이머 때문에 보드 전체가 리렌더링되지 않도록 분리한다.
- 불필요한 라이브러리를 사용하지 않는다.
- 키를 연타해도 입력이 밀리지 않아야 한다.


## 22. 코드 작성 규칙

- TypeScript를 사용한다.
- 게임 로직과 화면 코드를 분리한다.
- 이동, 밀기, 클리어 판정은 순수 함수로 작성한다.
- 좌표는 일관된 형식으로 다룬다. (행, 열)
- 매직 넘버 대신 의미 있는 상수를 사용한다.
- 컴포넌트를 적절히 분리한다.
- 한 파일에 지나치게 많은 코드를 작성하지 않는다.
- 중복 코드를 최소화한다.
- 의미가 명확한 변수명을 사용한다.


## 23. 금지사항

- 게임 엔진, 캔버스 라이브러리 사용 금지
- 요구사항에 없는 기능 임의 추가 금지
- 자동 풀이, 힌트 기능 금지
- 과도한 애니메이션 금지
- 화면이 흔들리는 효과 금지
- 자동 재생 사운드 금지
- 검증하지 않은 레벨 데이터 추가 금지
- 클리어 불가능한 레벨 추가 금지
- 모바일에서 조작하기 어려운 UI 금지
- 서버, 계정, 외부 API 연동 금지
