# PRD: 공항이 멈추면? — 세계 항공 네트워크 폐쇄 시뮬레이터 (가칭 SkyCut)

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.2 |
| 작성일 | 2026-09-17 |
| 산출물 | 인터랙티브 소개사이트 (웹) |
| 기간 | 미정 (섹션 12 참고) |

---

## 1. 개요

전 세계 공항을 노드, 직항 노선을 엣지로 하는 그래프를 만들고, 사용자가 공항이나 지역을 "폐쇄"하면 네트워크가 어떻게 무너지고 우회되는지를 3D 지구본 위에서 보여주는 웹 서비스다. 소개사이트 자체가 데이터 스토리텔링 페이지이자 체험형 데모 역할을 한다.

## 2. 문제 정의

- 세계 하늘길은 소수의 허브 공항에 크게 의존하지만, 일반인은 그 의존도를 체감하기 어렵다.
- 2010년 아이슬란드 화산 폭발, 코로나19 국경 폐쇄처럼 공항·영공 폐쇄는 실제로 반복해서 일어난다.
- 기존 항공 서비스(항공편 추적 등)는 "지금 어디 있나"를 보여줄 뿐, "무엇이 끊기면 어떻게 되나"를 실험하게 해주지 않는다.

## 3. 목표

### 3.1 제품 목표
1. 방문자가 공항을 직접 끄고 결과를 3초 안에 눈으로 확인할 수 있다.
2. "허브 중심 네트워크는 무작위 고장에는 강하지만 표적 공격에는 약하다"는 개념을 비전공자도 이해하게 한다.
3. 실제 사건(화산, 팬데믹)을 재현한 시나리오를 제공한다.

### 3.2 비목표 (이번 범위에서 하지 않음)
- 실시간 항공편 예약, 운임, 편별 지연 정보
- 좌석 수·운항 횟수를 반영한 정밀 수요 모델
- 모바일 앱 (반응형 웹만 지원)

## 4. 대상 사용자

| 사용자 | 기대 |
|---|---|
| 발표 청중 / 평가자 | 짧은 시간 안에 문제·해결·기술을 이해 |
| 일반 방문자 | 지구본을 돌리고 공항을 꺼보는 재미 |
| 데이터·네트워크에 관심 있는 학생 | 중심성, 최단경로 등 알고리즘 결과 확인 |

## 5. 사용자 스토리

- 방문자로서, 지구본에서 공항을 클릭해 폐쇄하고, 어떤 도시가 고립되는지 보고 싶다.
- 방문자로서, 출발지와 도착지를 골라 폐쇄 전후의 최단 경로(환승 횟수, 거리)를 비교하고 싶다.
- 방문자로서, "유럽 영공 폐쇄" 같은 시나리오 버튼 하나로 실제 사건을 재현해보고 싶다.
- 방문자로서, 가장 중요한 공항 순위를 보고 그 이유를 이해하고 싶다.
- 방문자로서, 공항을 무작위로 끌 때와 허브부터 끌 때 네트워크가 무너지는 속도를 비교하고 싶다.

## 6. 기능 요구사항

### 6.1 MVP (필수)

| ID | 기능 | 설명 | 수용 기준 |
|---|---|---|---|
| F1 | 지구본 네트워크 표시 | 주요 공항(점)과 주요 노선(호) 표시 | 첫 화면에 노선 1,000~3,000개, 흐름 애니메이션 포함 |
| F2 | 공항 검색·선택 | IATA 코드/도시명 검색, 클릭 선택 | 선택 시 공항 정보 패널 표시 |
| F3 | 공항 폐쇄 / 복구 | 선택 공항을 끄고 켜기, 다중 선택 가능 | 폐쇄 공항과 연결 노선이 시각적으로 구분됨 |
| F4 | 영향 분석 | 고립 공항 수, 연결 요소 변화, 부담이 늘어나는 공항 | 폐쇄 후 3초 이내 결과 표시 |
| F5 | 경로 비교 | 출발·도착 선택 → 폐쇄 전후 최단 경로 비교 | 환승 횟수, 총 거리, 경유 공항 표시 |
| F6 | 허브 순위 | 매개 중심성 기준 상위 공항 목록 | 상위 20개 표시, 클릭 시 지구본 이동 |

### 6.2 확장 (시간이 남으면)

| ID | 기능 | 설명 |
|---|---|---|
| E1 | 시나리오 모드 | 유럽 영공 폐쇄(2010 화산), 국경 폐쇄 등 프리셋 |
| E2 | 붕괴 곡선 비교 | 무작위 제거 vs 허브 우선 제거 시 최대 연결 요소 크기 그래프 |
| E3 | 지역 단위 폐쇄 | 국가·대륙 또는 지도에 그린 영역 단위로 폐쇄 |
| E4 | 실시간 항공기 배경 | OpenSky 위치 데이터를 작은 점으로 표시 + "지금 떠 있는 N대" |
| E5 | 최신 노선망 | OpenSky 운항 기록으로 최근 노선망 직접 구축 |
| E6 | 공유 링크 | 폐쇄 상태를 URL에 담아 공유 |

## 7. 데이터

| 데이터 | 출처 | 용도 | 주의점 |
|---|---|---|---|
| 공항 | OurAirports | 위치, 코드, 규모, 국가 | 대형·중형 공항 위주로 필터링 |
| 노선 | OpenFlights routes | 직항 노선 그래프 | 2014년 이후 갱신 중단 → "과거 기준 네트워크"로 명시 |
| 항공기 위치·운항 기록 (확장) | OpenSky Network API | E4, E5 | 비상업·연구용 조건, 호출 제한 확인 필요 |

### 7.1 전처리
1. 공항: 정기 여객 노선이 있는 공항만 남김. 규모 상위 약 1,000~3,000개로 축소.
2. 노선: 항공사 중복 제거 → 공항 쌍 단위 무방향(또는 방향) 엣지로 통합, 노선에 취항 항공사 수를 보조 가중치로 저장.
3. 거리: 공항 좌표로 대권거리(haversine) 계산해 엣지 가중치로 사용.
4. 결과를 정적 JSON으로 출력.

## 8. 알고리즘

| 목적 | 방법 | 실행 위치 |
|---|---|---|
| 최단 경로 (거리) | 다익스트라 | 브라우저 |
| 최소 환승 경로 | BFS | 브라우저 |
| 공항 중요도 | 매개 중심성 (필요 시 샘플링 근사) | 사전 계산 (파이썬) |
| 고립 지역 탐지 | 연결 요소 (Union-Find 또는 BFS) | 브라우저 |
| 부담 증가 공항 | 폐쇄 후 샘플 공항 쌍의 최단경로 재계산 → 경유 빈도 변화 | 브라우저 (샘플 수 제한) |
| 붕괴 곡선 (E2) | 노드 순차 제거 시 최대 연결 요소 비율 | 사전 계산 |

## 9. 기술 구성

- **데이터 처리**: Python, pandas, NetworkX
- **프론트엔드**: HTML/JS (또는 React), globe.gl(Three.js 기반) — 대안 CesiumJS, deck.gl
- **그래프 계산(브라우저)**: 자체 구현 또는 경량 라이브러리, 무거운 계산은 Web Worker로 분리
- **차트**: D3 또는 Chart.js
- **배포**: 정적 호스팅 (GitHub Pages, Vercel 등). MVP는 백엔드 없음
- **확장 시(E4, E5)**: OpenSky 호출을 대신하고 캐싱하는 작은 서버 필요

```
[OurAirports / OpenFlights]
        │  (Python 전처리, 중심성 사전 계산)
        ▼
  airports.json / routes.json / centrality.json
        │
        ▼
[브라우저] ── 지구본 렌더링 (globe.gl)
     └──── Web Worker: 최단경로·연결요소 재계산
```

## 10. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 첫 로딩 | 일반 노트북·유선 기준 5초 이내 인터랙션 가능 |
| 렌더링 | 기본 화면 30fps 이상 유지 |
| 폐쇄 후 분석 | 3초 이내 결과 표시 |
| 표시 개수 | 첫 화면 노선 1,000~3,000개 / 시뮬레이션 화면은 관련 노선 수백 개 이내 강조 |
| 저사양 대응 | 기기 성능에 따라 표시 노선 수를 줄이는 "가벼운 모드" |
| 반응형 | 데스크톱 우선, 모바일은 보기·기본 조작 가능 수준 |
| 데이터 출처 | 페이지 하단에 출처와 라이선스, 데이터 기준 시점 명시 |

## 11. 소개사이트 구성 (스크롤 흐름)

1. **히어로**: 노선이 흐르는 지구본 + "세계 하늘길은 몇 개의 공항에 기대고 있을까?"
2. **문제**: 실제 폐쇄 사례 소개 (화산, 팬데믹)
3. **허브 순위**: 매개 중심성 상위 공항과 쉬운 설명
4. **시나리오 재현** (E1)
5. **직접 해보기**: 공항 폐쇄 + 경로 비교 체험 섹션 (핵심)
6. **인사이트**: 무작위 vs 허브 제거 붕괴 곡선 (E2)
7. **기술 구조**: 데이터 파이프라인, 알고리즘, 성능 최적화
8. **한계와 향후 계획**: 노선 데이터 시점, 수요 미반영 등
9. **데이터 출처**

## 12. 일정 (초안, 기간 확정 후 조정)

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | 데이터 수집·전처리, 그래프 구축 | JSON 데이터, 노트북 |
| 2 | 지구본 렌더링 + 성능 테스트 (500 → 2,000 → 전체) | 기본 지구본 페이지 |
| 3 | 폐쇄·영향 분석·경로 비교 (F3~F5) | 동작하는 시뮬레이터 |
| 4 | 허브 순위, 소개사이트 스토리 섹션 | 소개 페이지 초안 |
| 5 | 확장 기능 (E1, E2 우선) | 시나리오, 붕괴 곡선 |

## 13. 성공 기준

- MVP 기능(F1~F6)이 발표 환경 기기에서 끊김 없이 동작한다.
- 처음 보는 사용자가 안내 없이 1분 안에 공항 하나를 폐쇄하고 결과를 해석할 수 있다.
- 발표에서 최소 1개의 실제 시나리오와 1개의 네트워크 인사이트를 시연한다.

## 14. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 노선 데이터가 오래됨 | 현재와 결과 차이 | 기준 시점 명시, 여유 있으면 E5로 보완 |
| 대규모 그래프 계산이 느림 | 인터랙션 지연 | 공항 수 축소, 사전 계산, Web Worker, 샘플링 |
| 노선이 많아 지구본이 뭉개짐 | 가독성 저하 | 표시 노선 제한, 폐쇄 관련 노선만 강조 |
| 발표 기기 성능 부족 | 프레임 저하 | 가벼운 모드, 사전 리허설 |
| 외부 API 정책 변경 (OpenSky) | 확장 기능 불가 | MVP는 정적 데이터만 사용하도록 설계 |
| 수요(좌석·운항 횟수) 미반영 | 결과 해석 한계 | 한계로 명시, 항공사 수를 보조 지표로 활용 |
