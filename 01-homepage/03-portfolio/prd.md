# 신입 개발자 포트폴리오 웹사이트 요구사항

## 1. 프로젝트 개요

### 목적

신입 개발자의 기술 역량과 프로젝트 경험을 보여주는
개인 포트폴리오 웹사이트를 제작한다.

단순한 자기소개 페이지가 아니라,
실제로 어떤 기술을 사용했고 어떤 문제를 해결했는지
채용 담당자와 개발자가 빠르게 확인할 수 있도록 구성한다.

### 대상

- IT 기업 채용 담당자
- 프론트엔드 개발자
- 백엔드 개발자
- 개발자 면접관

### 핵심 목표

1. 첫 화면에서 개발자의 정체성을 명확하게 전달한다.
2. 주요 프로젝트를 가장 중요한 콘텐츠로 보여준다.
3. 사용한 기술보다 실제 구현 경험과 문제 해결 과정을 강조한다.
4. GitHub와 프로젝트 결과물로 실제 개발 경험을 확인할 수 있도록 한다.
5. 모바일과 데스크톱 모두에서 깔끔하게 보이도록 한다.

# 22. 콘텐츠 원칙

포트폴리오의 모든 내용은 실제 경험을 기반으로 작성한다.

절대로 다음을 임의로 만들어내지 않는다.

- 존재하지 않는 프로젝트
- 사용하지 않은 기술
- 실제로 하지 않은 역할
- 가짜 성과
- 가짜 수치
- 존재하지 않는 회사
- 가짜 GitHub Repository

정보가 없는 경우 placeholder를 사용한다.

예:

[프로젝트 설명 입력]

[GitHub URL 입력]

# 25. Claude Code 작업 방식

작업을 시작하기 전에 반드시 현재 프로젝트 구조를 확인한다.

1. 프로젝트 구조 분석
2. 현재 사용 중인 기술 확인
3. 기존 코드 확인
4. SPEC.md 요구사항 분석
5. 구현 계획 수립
6. 필요한 컴포넌트 설계
7. 구현
8. 실행
9. 오류 확인
10. UI 확인
11. 수정
12. 최종 점검

기존 코드가 있는 경우
필요한 부분만 수정하고 이유 없이 삭제하지 않는다.

요구사항이 불명확한 경우
기존 프로젝트 구조와 일반적인 웹 개발 관례를 우선적으로 사용한다.

구현이 끝났다고 판단하기 전에
반드시 실제로 실행하여 오류가 없는지 확인한다.
