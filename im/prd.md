# PRD — 나의 목표 소개 페이지

## 1. 개요

클로드코드 과정 시작 전, 수강생들과 공유할 **개인 목표 소개 페이지**를 만든다.
단일 HTML 페이지(`index.html`) 하나로 완성하며, 별도 서버나 빌드 도구 없이 브라우저에서 바로 열 수 있어야 한다.

## 2. 페이지에 담을 내용

### 2-1. 이 과정에서 이루고 싶은 목표
- 이 과정을 끝까지 배워가며 마무리하는 것

### 2-2. 과정 중에 만들어보고 싶은 프로젝트
- 에어비앤비 호스트로서 일상에서 필요했던 **호스팅 자동화 + 수익 분석 시스템**
  - 정산 대시보드(수익 분석)와 게스트 응대 AI 도우미를 한 웹앱 안에 탭 두 개로 구성
- 개인용 프로젝트이며 현재 배포 계획은 없음

### 2-3. 클로드코드로 배우고 싶은 것
- 수업에서는 다루지 않은 언어나 프레임워크를 AI를 활용해 빠르게 익혀보고 직접 써보고 싶다

## 3. 디자인 컨셉 — 흑백 에디토리얼 + 토스식 구성 요소

참고 사이트 (**디자인 요소만 참고하고, 문구·카피는 사용하지 않는다**)
- 메인 ①: 중앙그룹 — 흰 바탕 흑백 톤, 비대칭 레이아웃, 거대한 한글 헤드라인, 세로로 쌓인 메뉴, 여백의 세로 텍스트
- 메인 ②: 토스 2020 디자이너 채용 페이지 — 세로 타임라인, 탭 전환, 어두운 대비 섹션, 스크롤 등장 효과
- 전체 뼈대와 분위기는 ①, 섹션 안의 구성 요소와 움직임은 ②에서 가져온다

## 4. 화면 구성

1. **최상단 검정 띠** — 화면 폭 전체, 얇은 검정 바(데스크톱 약 28px)
2. **헤더**
   - 왼쪽: 점 4개로 된 작은 심볼 + 이름(영문, 중간 굵기)
   - 오른쪽: 메뉴 3개(Goal / Project / Learn)를 가로가 아닌 **세로로 쌓아서** 배치, 영문 중간 굵기, 호버 시 밑줄
3. **왼쪽 여백의 세로 텍스트 (고정)**
   - 화면 왼쪽 가장자리에 90도 회전한 작은 글씨: 위쪽에 섹션 표시(현재 섹션 진하게, 나머지 옅은 회색), 아래쪽에 연도·저작권 표기
   - 모바일에서는 숨김
4. **히어로**
   - 흰 바탕, 헤드라인을 화면 왼쪽에서 약 1/3 지점부터 시작하는 **비대칭 배치**
   - 아주 굵은 한글 헤드라인 3줄, 화면을 압도하는 크기
   - 헤드라인 아래 넉넉한 간격 후 **얇은 검정 가로선** + 그 아래 작은 부제 한 줄
5. **01 Goal — 세로 타임라인**
   - 영문 섹션 라벨(중간 굵기, 중간 크기)로 시작, 본문 영역은 히어로와 같은 왼쪽 1/3 기준선에 정렬
   - 과정 여정을 세로 타임라인으로: 왼쪽에 굵은 단계 라벨, 오른쪽에 설명, 단계 사이는 얇은 가로선
6. **02 Project / 03 Learn — 탭 전환 영역**
   - 영문 섹션 라벨 아래 탭 버튼 2개, 선택된 탭은 검정 배경 + 흰 글씨의 알약(pill) 모양, 선택 안 된 탭은 회색 글씨
   - 탭을 누르면 내용 전환: 굵은 소제목 + 점(•)으로 시작하는 짧은 문장 목록
   - 프로젝트 탭에는 "PRIVATE · 배포 예정 없음" 작은 회색 태그
   - 이미지가 필요하면 **흑백(grayscale) 처리된 사각형 이미지 영역**으로 두고, 이미지가 없으면 옅은 회색 면으로 대체
7. **마무리 — 어두운 대비 섹션**
   - 페이지에서 유일한 검정 배경 섹션, 흰색 굵은 2줄 문장 + 흰 테두리 버튼 1개(클릭 시 페이지 링크 복사, "복사됨" 짧은 안내)
8. **푸터** — 흰 바탕, 작은 회색 글씨 한 줄

## 5. 디자인 요구사항

- **색**
  - 기본은 흑백: 배경 흰색(#FFFFFF), 텍스트 검정(#000000 ~ #111111), 보조 텍스트 회색(#8A8A8A), 옅은 선·면 #E5E5E5
  - 포인트 색은 사용하지 않거나, 쓴다면 파란색(#3182F6) 하나를 링크 복사 완료 안내 같은 아주 작은 곳에만 사용
  - 이미지는 모두 흑백
- **타이포**
  - 한글: 굵은 고딕(Pretendard 권장, 없으면 시스템 고딕), 헤드라인은 800~900 굵기, 줄 간격 1.2 전후, 자간 살짝 좁게
  - 영문(메뉴·섹션 라벨·로고): 깔끔한 그로테스크 산세리프(시스템의 Helvetica/Arial 계열로 대체 가능), 중간 굵기
  - 헤드라인 크기는 데스크톱에서 화면 폭의 약 5~6%, 본문은 16~18px
- **레이아웃**
  - 헤드라인과 본문은 화면 왼쪽 약 1/3 지점의 **공통 기준선**에 맞춰 정렬 → 왼쪽이 크게 비는 비대칭 구성 유지
  - 섹션 위아래 여백 크게(데스크톱 160~200px, 모바일 96px 안팎)
  - 카드·박스·그림자 없이 선과 여백만으로 구분
- **움직임**: 스크롤 시 섹션 라벨·헤드라인·본문이 아래에서 살짝 떠오르며 순서대로 등장, 탭 전환 시 부드럽게 교체, 왼쪽 세로 텍스트의 현재 섹션 표시가 스크롤에 따라 바뀜. prefers-reduced-motion 시 생략
- **반응형**
  - 모바일: 비대칭 기준선을 없애고 좌우 여백 20px의 1단 구조, 세로 메뉴는 햄버거 대신 헤더 오른쪽에 작게 그대로 쌓음, 세로 텍스트 숨김
  - 헤드라인은 화면 폭에 맞춰 줄바꿈
- **피할 것**: 컬러 사진, 여러 가지 포인트 색, 그라데이션, 그림자 카드, 둥근 카드 박스, 이모지 아이콘, 참고 사이트 문구 사용

## 6. 기술 요구사항

- HTML + CSS(+ 필요 시 소량의 JS)를 `index.html` 단일 파일로 작성
- 외부 라이브러리·프레임워크 사용하지 않음 (웹폰트만 예외, 없어도 동작)
- 스크롤 등장 효과·현재 섹션 표시는 IntersectionObserver, 탭 전환·링크 복사는 순수 JS로 직접 구현
- 세로 텍스트는 `writing-mode` 또는 `transform: rotate(-90deg)`로 구현
- 파일을 더블클릭해 브라우저에서 열면 바로 표시되어야 함

## 7. 완료 기준

- [ ] 세 섹션의 내용이 모두 빠짐없이 표시된다
- [ ] 첫 화면이 흰 바탕의 비대칭 대형 헤드라인 + 세로 메뉴 구성으로 보인다
- [ ] 페이지 전체가 흑백 톤으로 유지되고, 마무리 섹션만 검정 배경이다
- [ ] 탭 전환, 링크 복사, 현재 섹션 표시가 정상 동작한다
- [ ] 모바일 화면(375px)과 데스크톱(1280px)에서 레이아웃이 깨지지 않는다
- [ ] 브라우저에서 `index.html`을 열었을 때 오류 없이 렌더링된다
